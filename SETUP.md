# IntelX — Setup & Run Notes

Problem Statement 26228 (Ministry of Defence / Indian Army DGIS). This document is the practical
"how do I actually run this" companion to `README.md`.

## 1. Requirements

- Python 3.11+ (tested on 3.11 and 3.14)
- Node.js 18+ / [Bun](https://bun.sh) (this project is Bun-only — see `packageManager` in `package.json`; there is no `package-lock.json`, only `bun.lock`)
- No internet access is required at runtime — the system is fully offline/air-gapped. Internet
  access is only needed once, up front, to install the Python and npm dependencies below.

## 2. Backend setup

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Run the API server:

```bash
uvicorn backend.main:app --host 0.0.0.0 --port 8000
```

(run from the repo root, with the venv above active, so the `backend` package resolves).

Verify it's up:

```bash
curl http://localhost:8000/health
```

Run the test suite:

```bash
pytest tests/ -v
```

## 3. Frontend setup

```bash
bun install
bun run dev
```

Open `http://localhost:3000`. The dashboard has two modes:

- **Scenario Replay** — six canned, reproducible attack scenarios (clean baseline, poisoned
  dataset, backdoored/substituted model, tampered inference record, inference replay/reordering,
  post-hoc audit-log tampering) generated fresh on first run under `test_assets/`.
- **Live Analysis** — upload your own ONNX/PyTorch/TorchScript model, a zipped COCO or YOLO
  dataset, and/or an image, and the exact same backend pipeline runs against your real files.

Set `NEXT_PUBLIC_API_URL` if the backend isn't at `http://localhost:8000`.

## 4. Runtime data locations

These are created automatically and are gitignored (do not commit them):

| Path                              | Purpose                                                                                                                                                                                                                                        |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `uploads/`                        | Files uploaded via the Live Analysis API (models, dataset archives, probe images)                                                                                                                                                              |
| `keys/provenance_signing_key.pem` | Persisted Ed25519 private key used to sign inference provenance records. Generated on first run if absent. Back this up if you need old signatures to remain independently verifiable after a redeploy.                                        |
| `audit_log/ledger.jsonl`          | The persisted, hash-chained tamper-evident audit ledger. Append-only; do not hand-edit.                                                                                                                                                        |
| `intelx.db`                      | SQLite database. Every uploaded model fingerprint, dataset analysis, inference record, and assurance report (both from Live Analysis and from Scenario Replay) is persisted here and retrievable by ID — nothing is recomputed-then-discarded. |
| `test_assets/`                    | Synthetic COCO/YOLO dataset + ONNX models generated by the scenario harness (`backend/scenarios/asset_generator.py`)                                                                                                                           |

## 5. Key API endpoints

| Method   | Path                                             | Purpose                                                                               |
| -------- | ------------------------------------------------ | ------------------------------------------------------------------------------------- |
| POST     | `/api/model/upload`                              | Upload a real model file, get back a real SHA-256 fingerprint                         |
| POST     | `/api/model/parameter-analysis`                  | Real ONNX weight-statistics analysis (white-box only)                                 |
| POST     | `/api/model/behaviour-battery`                   | Real reference-vs-candidate model behavioral comparison                               |
| POST     | `/api/dataset/upload`                            | Upload a zipped COCO/YOLO dataset                                                     |
| POST     | `/api/dataset/analyze-profile`                   | Run the full data-integrity pipeline on a real dataset                                |
| POST     | `/api/inference/execute`                         | Run a real model against a real image, get a signed provenance record                 |
| POST     | `/api/inference/verify`                          | Verify a provenance record's cryptographic binding                                    |
| GET      | `/api/audit/entries`                             | Read the full tamper-evident audit trail                                              |
| POST     | `/api/report/generate`                           | Compile findings into a governance-ready`AssuranceReport` (persisted to the database) |
| GET/POST | `/api/scenarios/list`, `/api/scenarios/run/{id}` | Canned reproducible attack scenarios A–F                                              |
| GET      | `/api/auth/whoami`                               | Verify the presented `X-API-Key` against the RBAC gate and resolve its role           |
| POST     | `/api/report/{report_id}/decision`               | Record an analyst's final disposition decision on a stored report (hash-chained audit entry) |
| GET/DELETE | `/api/uploads/`, `/api/uploads/{upload_id}`    | List/delete raw staged uploads (models, dataset archives, probe images); delete requires the `admin` role |

### Real database-backed history/lookup endpoints

Every one of these reads from `intelx.db`, not from in-memory state — restart the server and the
data is still there:

| Method | Path                                                         | Purpose                                                                                                                                |
| ------ | ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/model/list`, `/api/model/{model_id}`                   | List/fetch every model ever fingerprinted                                                                                              |
| GET    | `/api/dataset/history`, `/api/dataset/history/{analysis_id}` | List/fetch every dataset analysis ever run                                                                                             |
| GET    | `/api/inference/list`, `/api/inference/record/{record_id}`   | List/fetch every inference record ever created                                                                                         |
| POST   | `/api/inference/record/{record_id}/verify`                   | Verify a record by ID alone — the server pulls the authoritative copy from the database rather than trusting a client-resent JSON body |
| GET    | `/api/report/list`, `/api/report/{report_id}`                | List/fetch every assurance report ever generated (scenario replay and live analysis alike)                                             |

Full interactive API docs are available at `http://localhost:8000/docs` once the backend is running.

**Path sandboxing**: any endpoint that takes a "server-local path" (`model_path`, `coco_path`,
`image_path`, etc.) only accepts paths that resolve inside `uploads/`, `test_assets/`, or
`real_validation/` (`backend/api/path_safety.py`). Upload the file via the corresponding
`/upload` endpoint first and pass back the `saved_path` it returns — a path outside these
directories is refused with 403, even if it exists and is readable, to prevent using these
endpoints to read arbitrary files on the host.

## 6. Reproducing the test scenarios manually

```python
from backend.scenarios.scenario_manager import ScenarioManager
mgr = ScenarioManager()
mgr.run_scenario_a_clean()              # clean baseline
mgr.run_scenario_b_poisoned()           # poisoned dataset / malicious contributor
mgr.run_scenario_c_model_compromised()  # substituted + backdoored model
mgr.run_scenario_d_tampered_inference() # post-hoc inference tampering
mgr.run_scenario_e_replay()             # inference replay & reordering attack
mgr.run_scenario_f_audit_tamper()       # post-hoc audit-log modification
```

Each call appends real, hash-chained entries to the shared audit ledger (`backend/audit/audit_log.py:shared_ledger`) — see `docs/example_audit_log.json` for a captured example spanning all six scenarios end-to-end.
